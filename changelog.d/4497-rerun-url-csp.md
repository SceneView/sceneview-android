- **Website: a recording hosted elsewhere opens on the AR session page ([#4497](https://github.com/sceneview/sceneview/issues/4497)).** `sceneview.github.io/rerun/?url=<link to a .rrd>` is the link the apps and the docs tell you to share, but the page's own security policy only let it download from a fixed list of hosts, so a recording on your own domain, an R2 or S3 bucket or a GitHub repository never loaded. The page now downloads from any `https` address; nothing else in its policy changed. The host still has to allow cross-origin requests (CORS), and the docs now say so and name what works: a public GitHub repository's `raw.githubusercontent.com` link and GitHub Pages do, a GitHub release asset does not (checked 2026-10-13); an R2 or S3 bucket does with a CORS rule. When a link cannot be opened, the page says so on screen instead of showing an empty viewer, with the cause when the browser reveals it (no file at the address, not a Rerun recording, a link that does not end in `.rrd`, a link that carries a password) and the possible causes when it does not (the host forbids the read from another site, or the link is wrong, private or expired). The recording's link also stays out of the site's analytics: this page reports its address without the `?url=` part, a page of the site opened from it no longer receives the link as its referrer, and a click on **Download** is no longer recorded with the link. **Download** on a recording hosted elsewhere opens in a new tab instead of replacing the viewer.
