- **An AR frame loop that keeps failing now says so, instead of leaving the screen on "starting" ([#4510](https://github.com/sceneview/sceneview/issues/4510)).** `ARSceneView` caught whatever a frame threw and only wrote `ARCore session update failed` to logcat, so a session whose every frame failed kept a live camera image and never told the app. A loop that has thrown on every frame for about 1.5 s is now reported through `onSessionFailed` / `onSessionFailure`, once per exception type; a single bad frame is still only logged, and the loop keeps running. A throw from the app's own `onSessionUpdated` or `onTrackingFailureChanged` is logged under that callback's name and no longer skips the other callback. The Android demo files two things with its crash reports when collection is on: the exception behind an AR failure it has no code for, and an AR session that received camera frames for 10 s without ever tracking, with ARCore's reason. This is hardening and diagnosis for the Play report in #4510, whose cause is not established yet — not its fix.
