- **Android demo: the store build can no longer be pinned to a state that never happened ([#4555](https://github.com/sceneview/sceneview/issues/4555)).** The QA seam that pins a screen to a named state for emulator captures (`--ez qa_mode true --es qa_state <id>`: a "hosted" Cloud Anchor, a "streaming" Point & Ask answer, the Home still) was reachable on the Play build too, because `qa_mode` is an intent extra any app on the phone can send. A release build now ignores `qa_state` whatever `qa_mode` says; `qa_mode` itself still only freezes animations there. Debug builds (the `.qa` test app, the APK attached to GitHub releases) keep the seam, which the Maestro flows use.
